# 03 安装与配置

> [!info] 参考
> <https://yeasy.gitbook.io/docker_practice/03_install>
> Ubuntu 专页：<https://yeasy.gitbook.io/docker_practice/03_install/3.1_ubuntu>

## 3.1 选哪种安装方式

| 方式 | 适用 | 说明 |
| --- | --- | --- |
| **APT 官方仓库** | 服务器 / 生产 | 可升级、可锁版本、卸载干净，**推荐** |
| 官方脚本 `get.docker.com` | 本地快速试用 | 省事，但不利于版本管理 |
| Docker Desktop | Windows / macOS | 自带图形界面和 K8s |
| 发行版自带包 | — | 版本往往很旧，**不建议** |

> [!warning] 不要直接 `apt install docker.io`
> 发行版仓库里的版本通常落后很多，且与官方包冲突。要么用 Docker 官方 APT 源，要么用官方脚本。

## 3.2 Ubuntu 用 APT 安装

环境按 Ubuntu 22.04 / 24.04 LTS 写，其他版本把 `ubuntu` 换成对应发行版即可。

### 3.2.1 卸载旧版本

```bash
for pkg in docker.io docker-compose docker-compose-v2 docker-doc podman-docker containerd runc; do
    sudo apt remove $pkg
done
```

### 3.2.2 配置官方源

```bash
sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings

sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF
```

### 3.2.3 安装并启动

```bash
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

sudo systemctl enable --now docker
```

> [!tip] 这几个包分别是什么
> `docker-ce` 引擎本体 · `docker-ce-cli` 命令行 · `containerd.io` 底层运行时 · `buildx-plugin` 多架构构建 · `compose-plugin` 提供 `docker compose` 子命令。

### 3.2.4 免 sudo（可选）

```bash
sudo groupadd docker
sudo usermod -aG docker $USER
```

重新登录后生效。

> [!warning] 安全提醒
> `docker` 组权限**等价于 root**（可以挂载宿主机根目录）。多人共用的生产机上不要随便加人；更稳妥的做法是用 Rootless 模式。

### 3.2.5 验证

```bash
docker run --rm hello-world
docker version
docker info
```

## 3.3 配置镜像加速器

国内直连 Docker Hub 经常超时。思路是给 daemon 配 `registry-mirrors`。

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json <<'EOF'
{
  "registry-mirrors": ["https://<your-registry-mirror>"]
}
EOF

sudo systemctl daemon-reload
sudo systemctl restart docker
```

验证：

```bash
docker info | grep -A2 "Registry Mirrors"
```

> [!warning] 加速器现状
> 2024 年中起，阿里云、网易、百度等公共加速服务陆续关停，网上教程里的地址大多已失效。更可靠的做法是：用云厂商**内网**镜像地址、自建 pull-through cache，或直接配 HTTP 代理。

> [!tip] 代理方式
> 有外网代理时，可在 `/etc/systemd/system/docker.service.d/proxy.conf` 里配 `HTTP_PROXY` / `HTTPS_PROXY`，然后 `systemctl daemon-reload && systemctl restart docker`。

## 3.4 数据目录与日志

默认镜像和容器数据都在 `/var/lib/docker`，磁盘紧张时迁到数据盘：

```json
{
  "data-root": "/data/docker",
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "3" }
}
```

写进 `/etc/docker/daemon.json` 后重启生效。**日志不限制大小是磁盘被打满的头号原因。**

## 3.5 Windows / macOS

装 **Docker Desktop** 即可，它内部跑一台 Linux 虚拟机。

- Windows 需要开启 WSL2 或 Hyper-V
- 镜像加速在 `Settings → Docker Engine` 里改同一份 JSON，点 `Apply & restart`
- WSL2 下容器内访问 Windows 文件用 `/mnt/c/...`，跨文件系统 IO 较慢，项目尽量放 WSL 内部

## 3.6 常见安装后问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Cannot connect to the Docker daemon` | 服务没起 | `sudo systemctl start docker` |
| `permission denied ... docker.sock` | 用户不在 docker 组 | 加入组并重新登录 |
| 拉镜像卡住 / timeout | 网络 | 配加速器或代理 |
| `daemon.json` 改完起不来 | JSON 语法错 | `sudo dockerd --validate` 或检查逗号 |

更多错误见 [[10-镜像速查与排错]]。
