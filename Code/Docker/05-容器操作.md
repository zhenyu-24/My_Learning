# 05 容器操作

> [!info] 参考
> <https://yeasy.gitbook.io/docker_practice/05_container>

## 5.1 启动：`docker run`

```bash
docker run [OPTIONS] IMAGE [COMMAND] [ARG...]
```

高频参数：

| 参数 | 作用 | 示例 |
| --- | --- | --- |
| `-d` | 后台运行 | `docker run -d nginx` |
| `--name` | 指定名字 | `--name web` |
| `-p` | 端口映射 | `-p 8080:80` |
| `-v` | 挂载数据 | `-v data:/data` |
| `-e` | 环境变量 | `-e TZ=Asia/Shanghai` |
| `--network` | 指定网络 | `--network mynet` |
| `--restart` | 重启策略 | `--restart unless-stopped` |
| `--rm` | 退出即删除 | `--rm` |
| `-it` | 交互 + 终端 | `-it ubuntu bash` |
| `--entrypoint` | 覆盖入口命令 | `--entrypoint /bin/sh` |

常用组合：

```bash
# 后台跑 web 服务并映射端口
docker run -d --name web -p 8080:80 --restart unless-stopped nginx

# 跑完就删的一次性任务
docker run --rm -it ubuntu:24.04 bash

# 带环境变量和时区
docker run -d --name mysql \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -e TZ=Asia/Shanghai \
  -p 3306:3306 \
  -v mysql-data:/var/lib/mysql \
  mysql:8
```

> [!tip] `-p 8080:80` 的顺序
> **宿主机端口 : 容器端口**。只写一个端口（`-p 80`）时 Docker 随机分配宿主机端口，用 `docker port web` 查。

> [!warning] 前台 vs 后台
> `-d` 只是让 Docker 把日志和输入分离，容器里**主进程必须持续运行**。像 `ubuntu` 这种默认命令跑完就退的镜像，加 `-d` 也会立刻退出——用 `-dit ... bash` 或给它一个长期运行的命令。

## 5.2 查看与日志

```bash
docker ps                 # 运行中的容器
docker ps -a              # 包括已停止的
docker ps -a --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

docker logs web           # 全部日志
docker logs -f web        # 跟踪
docker logs --tail 100 web
docker logs --since 10m web

docker inspect web        # 完整 JSON：IP、挂载、环境变量
docker stats              # 实时 CPU / 内存 / 网络（类似 top）
docker top web            # 容器内进程
```

> [!tip] 排查问题的顺序
> `docker ps -a` 看状态和退出码 → `docker logs` 看应用报错 → `docker inspect` 看配置是否如预期 → `docker exec` 进去手动验证。

## 5.3 停止、重启、删除

```bash
docker stop web           # 先 SIGTERM，10 秒后 SIGKILL
docker stop -t 30 web     # 给 30 秒优雅退出
docker kill web           # 直接 SIGKILL
docker restart web

docker rm web             # 删已停止的容器
docker rm -f web          # 强制删运行中的

docker container prune    # 清理所有已停止容器
```

退出码怎么看：`docker ps -a` 的 `STATUS` 列会显示 `Exited (1)`，`1` 一般是应用自身报错，`137` 多半是被 OOM kill 或 `kill -9`。

## 5.4 进入容器

| 方式 | 说明 | 建议 |
| --- | --- | --- |
| `docker exec` | 新起一个进程 | **推荐** |
| `docker attach` | 附加到 PID 1 | 慎用，`Ctrl-C` 可能把容器停了 |

```bash
docker exec -it web bash
docker exec -it web sh            # Alpine 等精简镜像
docker exec -u root -it web bash  # 指定用户
docker exec -w /app web ls        # 指定工作目录
docker exec web env               # 不进容器执行单条命令
```

> [!warning] 进不去怎么办
> 镜像里可能根本没装 shell（如 `distroless`）。此时用 `docker cp` 拷文件出来，或临时起一个带工具的 sidecar 容器挂载同一个卷。

## 5.5 在容器和宿主机之间复制文件

```bash
docker cp web:/etc/nginx/nginx.conf ./nginx.conf
docker cp ./app.conf web:/etc/nginx/conf.d/app.conf
docker cp web:/var/log/nginx ./logs
```

> [!tip] `docker cp` 是急救手段
> 需要长期共享文件请用数据卷或绑定挂载（见 [[07-数据与网络]]），`cp` 进去的改动在容器重建后就没了。

## 5.6 资源限制

```bash
docker run -d --name app \
  --cpus 2 \
  --memory 1g \
  --memory-swap 2g \
  --pids-limit 200 \
  myapp:v1
```

- 超过内存限制时容器被 OOM killer 杀掉，退出码 137
- `--cpus 2` 表示最多用 2 个核，`--cpus 0.5` 表示半个核
- 限制不是"预留"，只是上限；要保证下限需用编排系统的 requests

> [!tip] 出问题时先看是不是 OOM
> `docker inspect app | grep OOMKilled` 返回 `true` 就是内存打爆了。

## 5.7 重启策略

| 策略 | 行为 |
| --- | --- |
| `no` | 默认，不自动重启 |
| `on-failure[:N]` | 非 0 退出时重启，最多 N 次 |
| `always` | 总是重启（包括 daemon 重启后） |
| `unless-stopped` | 总是重启，除非人为 stop |

单机部署一般用 `unless-stopped`；跑一次性任务不要加重启策略。

## 5.8 创建但不启动

```bash
docker create --name standby nginx:1.28   # 只创建不启动
docker start standby
docker export -o backup.tar standby       # 导出文件系统
docker commit standby nginx:custom        # 固化成镜像
```
