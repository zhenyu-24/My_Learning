# 04 镜像管理

> [!info] 参考
> <https://yeasy.gitbook.io/docker_practice/04_image>

## 4.1 拉取

```bash
docker pull nginx:1.28
docker pull registry.example.com:5000/team/app:v1
```

`docker run` 时如果本地没有镜像，会自动 pull，所以单独 pull 主要是为了**提前下载**或**固定版本**。

> [!tip] 拉特定架构
> 在 ARM 机器上想跑 x86 镜像（或反之），用 `docker pull --platform linux/amd64 nginx`。但能否运行取决于内核是否支持模拟，通常需要 QEMU/binfmt。

## 4.2 查看

```bash
docker images                    # 列出本地镜像
docker images nginx              # 只看 nginx
docker image inspect nginx:1.28  # 详细信息：架构、环境变量、入口命令
docker history nginx:1.28        # 看每层是怎么来的、占多大
```

`docker history` 是排查"镜像为什么这么大"的第一手段：哪层几百 MB 一眼就能看出来。

## 4.3 删除

```bash
docker rmi nginx:1.28     # 删镜像（有容器在用会失败）
docker rmi -f nginx:1.28  # 强制
docker image prune        # 清理悬空镜像（<none>）
docker image prune -a     # 清理所有没被容器使用的镜像
```

> [!warning] `<none>` 从哪来
> 重新 build 同一个 tag 后，旧镜像失去 tag 就变成 `<none>`。属于正常现象，定期 `prune` 即可。

## 4.4 用 commit 理解分层

`commit` 把容器的可写层固化成一个新镜像，适合**临时试验**，不适合交付。

```bash
docker run -it --name demo ubuntu:24.04 bash
# 容器内：
#   apt update && apt install -y curl
#   exit

docker commit demo myubuntu:curl
docker images myubuntu
```

缺点很明确：

- 别人看不到这个镜像**怎么来的**，无法复现
- 容易夹带临时文件、密码、缓存
- 层会越叠越多

> [!tip] 正确姿势
> 用 Dockerfile 重建，见 [[06-Dockerfile]]。commit 只用于"我就想先存一下现场"。

## 4.5 导入导出

### 4.5.1 镜像搬运：`save` / `load`

无外网、无 Registry 时常用（保留完整分层和历史）：

```bash
docker save -o app.tar myapp:v1
docker load -i app.tar

# 配合 gzip 减小体积
docker save myapp:v1 | gzip > app.tar.gz
gunzip -c app.tar.gz | docker load
```

### 4.5.2 文件系统导入：`import`

把 rootfs 压缩包直接变成一个单层镜像，**丢历史**：

```bash
docker import rootfs.tar.gz mybase:v1
```

### 4.5.3 容器快照：`export` / `import`

```bash
docker export -o snap.tar mycontainer
docker import snap.tar mysnap:v1
```

`export` 导出的是容器当时的文件系统（不含元数据、不含历史），和 `save` 不是一回事。

| 命令 | 对象 | 保留分层/历史 | 用途 |
| --- | --- | --- | --- |
| `save` / `load` | 镜像 | 是 | 离线搬运镜像 |
| `export` / `import` | 容器 | 否 | 做基础 rootfs、抢救现场 |

## 4.6 打标签与推送

```bash
docker tag myapp:v1 registry.example.com/team/myapp:v1
docker login registry.example.com
docker push registry.example.com/team/myapp:v1
```

> [!tip] tag 的规则
> `docker tag` 只是给同一个镜像 ID 起别名，不复制数据。所以 `latest` 和 `v1` 可以指向完全相同的镜像。

## 4.7 空间清理

```bash
docker system df          # 看镜像/容器/卷/缓存各占多少
docker system prune       # 清停止的容器、悬空镜像、未用网络
docker system prune -a    # 连未使用的镜像一起清（慎用）
docker builder prune      # 清构建缓存（通常是大头）
```

> [!warning] 别在服务器上随手 `prune -a`
> 会把"暂时没跑但需要保留"的镜像删掉，下次启动又得重新拉。先 `docker system df` 看清楚再动手。
